Written during development, following [`docs/planning/v3/RE-MEASURE.md`](../planning/v3/RE-MEASURE.md) in response to issue #149 (next-major trigger watch T-8/T-9 fired) and issue #145 (upstream v11.5.0 sync).

## F-01 — Next-major triggers fired on SDK minor/patch updates, not protocol breaks

### The measurement

The trigger watch (`scripts/check-v4-triggers.mjs`) flagged:
- T-8: `@modelcontextprotocol/server` moved past 2.0.0 (measured at 2.3.1)
- T-8: `@modelcontextprotocol/node` moved past 2.0.0 (measured at 2.1.1)
- T-8: `@modelcontextprotocol/client` moved past 2.0.0 (measured at 2.3.1)
- T-9: `@modelcontextprotocol/conformance` moved past 0.2.0-alpha.11 (measured at 0.2.0-alpha.12)

### Analysis & Re-scoping

Testing the updated SDK dependencies against the running server and test suite reveals:
1. The protocol version remains `2026-07-28`.
2. The `server.json` schema remains `2025-12-11`.
3. The draft changelog at `modelcontextprotocol.io` remains the empty stub (T-1 did not fire).
4. No protocol-level breaking changes exist between SDK 2.0.0 and 2.3.1.
5. All 1,728 MCP unit and integration tests continue to pass without modifications to client or server wire protocols.

**Conclusion:** Cutting a major version would be a false version inflation. Under SemVer, backwards-compatible dependency bumps and security hardening belong in a consolidated dependency and upstream maintenance release.

## F-02 — Upstream v11.5.0 sync: Buffer pool leak security fix and operation catalogue expansion

### The measurement

Upstream CyberChef released v11.5.0 (issue #145), containing:
- 1 new operation: `ParsePGPKey.mjs`
- 31 modified operations, including 17 image operations addressing buffer pool security leaks where uninitialized memory was returned instead of clean slice copies.
- 1 operation removed upstream: `RandomPrime.mjs` (unstable prime generation).

Syncing these changes:
- Adds `src/core/operations/ParsePGPKey.mjs` with test coverage in `tests/operations/tests/PGP.mjs`.
- Updates the operation catalogue count from 504 to 505.
- Fixes the buffer pool vulnerabilities across image manipulation operations.

## F-03 — Tool surface re-measurement and canonical table synchronization

### The measurement

Running `npm run measure:surfaces` over a live client and server yields:

| Surface | Tools | Bytes | KB | listTools latency |
|---|---|---|---|---|
| index | 23 | 15,620 | 15 KB | 28ms |
| curated | 120 | 109,548 | 107 KB | 68ms |
| all | 546 | 427,123 | 417 KB | 132ms |

Comparing against v4.2.0:
- `index` remains strictly bounded at 23 tools / 15,620 bytes (0 change).
- `curated` remains at 120 tools / 109,548 bytes (0 change).
- `all` increased by 1 tool (545 -> 546) and +417 bytes (426,706 -> 427,123 bytes) due to `cyberchef_parse_pgp_key`.
- Round-trip cost: index (15,620) + one schema (1,778) = 17,398 bytes.
- Efficiency multiplier: `427,123 / 17,398 = 24.6x cheaper` than `all`.

All canonical tables and documentation figures are updated and verified by `tool-surface-figures.test.mjs` and `check-version-consistency.mjs`.
