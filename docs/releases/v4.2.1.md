# v4.2.1 — Security dependency refresh

**Released:** 2026-11-26
**Upstream base:** CyberChef v11.5.0 (unchanged)
**Licence:** GPL-3.0-or-later
**Node:** `>=26 <27`

## What changed, in one paragraph

A dependency release. **No source code changed.** Every advisory below lives in a dependency or the
container base image. It is fixed by the version resolved in `package-lock.json` or by the
base-image digest in `Dockerfile.mcp`. Installing from npm with an existing lockfile needs one
extra step; see the hono note below. Four open Dependabot pull requests (#176,
#181, #182, #177) are folded in. That makes this the first release of the runtime updates #170
landed on `master` after v4.2.0. The version string is read at startup, so a running v4.2.1 server
reports `4.2.1` in `serverInfo`, the startup log and the `cyberchef_mcp_build_info` metric.

HTTP/2 denial of service) in the Chainguard Node v26.12.1 base. The advisory was published after the
last green scan on `master`, so `master` would have failed the same way. Both `Dockerfile.mcp`
stages are re-pinned to the 2026-11-26 Chainguard digests, which run Node v26.13.1
(`nodejs-26-26.13.1-r1`; fixed in 26.13.1-r0):

| Stage | Tag | Digest |
|---|---|---|
| builder | `cgr.dev/chainguard/node:latest-dev` | `sha256:42e9e83d31a228a12c991c4c332205409cb7b46bd29a3e9519f6c98f710fbea1` |
| runtime | `cgr.dev/chainguard/node:latest` | `sha256:3f0d2afa09a5b4ccf8cb9caf9457343d0128a7e1ca63ebe5f9932420fe96cfa4` |

The `.trivyignore` entry for CVE-2026-85393 (node-forge) is removed. It said to remove it once a
fixed release existed, and node-forge 1.4.4 is one, so a scan that reports it again now fails.

The two hono packages sit under the Streamable HTTP transport. The fixed releases are inside the
ranges `@modelcontextprotocol/node` already declares, so `npm update` lifted them and no
`overrides` entry was added.

**If you install from npm with an existing lockfile, refresh these two yourself.** The published
package ships no lockfile, and `@modelcontextprotocol/node` still accepts affected versions, so
upgrading `cyberchef-mcp` alone leaves whatever your lockfile already records. Run
`npm update hono @hono/node-server` to get `hono` >= 4.13.16 and `@hono/node-server` >= 2.1.11.
The Docker image and a fresh install are not affected, because the image builds with `npm ci`
from this repository's lock.

The direct floors are raised so npm consumers cannot resolve an unpatched or untested version:
`node-forge` `^1.4.4` and `dompurify` `^3.5.0` (the versions locked and tested here).

  every version affected. It is what `npm audit --omit=dev` still reports (4 low: `elliptic` and the

  MODERATE: development-only. They are fixed only in the next majors (`glob` 14.0.2, `minimatch`
  11.0.1), and a major bump of build tooling does not belong in a patch release. Neither is in the
  image, which runs `npm prune --omit=dev`.
