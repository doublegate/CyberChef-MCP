# Charter: v4.3.0 — `ext-proj-int`, phase 2

> Run [`../../v3/RE-MEASURE.md`](../../v3/RE-MEASURE.md) first.

## Intent

The second slice of the same programme as [v4.2.0](./v4.2.0.md), separated because the programme was
scoped at 24 weeks and one release cannot hold it.

## The reason this is a separate charter rather than "more of v4.2.0"

Every tool added since v3.3.0 has grown the **default index surface**, and the index is the surface
the whole design rests on. Twelve new registry tools doubled it in v3.3.0. A registry tool has no
navigation path — one that is not listed cannot be called at all — so it cannot be hidden behind the
index the way an operation can.

**So this charter's first task is a measurement, not a feature**: re-run `npm run measure:surfaces`
and decide whether the index can absorb another slice before choosing what goes in it. As of
v3.9.0 the index is 42 tools / 44,493 bytes against 545 / 424,897 for `all`.

## Candidate scope

Deferred to measurement, as above. Any tool taken here must be justified against the index cost as
well as against the three-gap bar.

## Trigger

v4.2.0 shipped, and the surface measurement shows headroom.

## Kill criteria

- The index surface grows past the point where it stops being meaningfully cheaper than `curated`
  (107,739 bytes as of v3.9.0). At that point the answer is a **better surface mechanism**, not
  fewer tools — see [v4.7.0](./v4.7.0.md).
- The same three-gap and licence criteria as v4.2.0.
