# Charter: v4.1.0 — The entry point, and the landmine under the test suite

> Run [`../../v3/RE-MEASURE.md`](../../v3/RE-MEASURE.md) first.

## Intent

`src/node/mcp-server.mjs` calls `runServer()` **at module scope, with no main-module guard**, and
`runServer().catch` ends in `process.exit(1)`. Importing the module therefore starts a real stdio
server and arms a process exit — in every test file that imports it.

## Evidence, not suspicion

Verified during v3.9.0 by importing the module in a bare script: the full startup banner appears.
The consequence was not theoretical. v3.9.0's first CI run failed `mcp-test` on **both** Node
versions while passing locally twice, because four test files repoint `CYBERCHEF_RECIPE_STORAGE` at
a temp directory, import the server, and then delete that directory — and a save landing afterwards
killed the vitest worker. Recorded as **F-13** in `docs/internal/v3.9.0-findings-log.md`.

v3.9.0 fixed the race by leaking four temp directories. That is a workaround and says so in the
code. An independent reviewer reached the same diagnosis unprompted and proposed the same fix.

## Candidate scope

- A main-module guard, or an exported `close()`, or both — the reviewer suggested the second and it
  is the better shape for tests.
- Restore the four deleted teardowns once the server can be shut down.
- A test that **imports the module and asserts no server started**, which is the regression gate;
  without it this reverts silently, which is exactly how it arrived.

## Why its own release

It changes the entry-point semantics of the most important file in the repository. `npm run mcp`,
the Docker `CMD`, the `bin` entry and roughly forty documented quick-starts all run that file
directly. Deliberately **not** done inside v3.9.0's bot-review ceremony on a release whose CI had
already failed once.

## Trigger

None needed — the defect is measured and present. This is the one charter here that is ready now.

## Kill criteria

- If a guard cannot be written that keeps `node src/node/mcp-server.mjs`, the Docker `CMD` and the
  `bin` entry all working, **stop** and document why; the workaround is survivable.
- If removing the module-scope call breaks the era decision in `serveStdio` (2026-07-28 vs 2025),
  that is a protocol regression and outranks test ergonomics.
