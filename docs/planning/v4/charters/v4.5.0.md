# Charter: v4.5.0 — Magic, and scoring that is measured rather than asserted

> Run [`../../v3/RE-MEASURE.md`](../../v3/RE-MEASURE.md) first.

## Intent

`cyberchef_magic` is the tool a caller reaches for **before** they know what they are looking at, so
it is the one whose ranking matters most and the one with the least evidence behind it. This charter
gives it a measured accuracy figure and improves the ranking against that figure — not against
intuition, which is how the last defect got in.

This is the in-scope half of a rejected label. `v4.0.0-plan.md` rejected *"ML-optimised operation
selection"* — a learned model in the selection path — and was right to. It also recorded that
**improving the selection this server already does is not ML and is real work.** That is this
charter.

## The evidence, all of it already in the tree

| | |
|---|---|
| **Ranking has been wrong in a way nobody noticed** | v3.9.0, issue #130: upstream's comparator clamps any file-signature match to 500 while text keeps chi-squared scores in the thousands, so a detected **container outranked the plaintext extracted from it** — a three-layer payload put the decoded answer at rank 3, beneath raw gzip |
| **The first fix was also wrong** | promoting any longer UTF-8 result handed rank 1 to a `From Hexdump` branch returning one character. The fix had to be anchored on the container |
| **Language detection is documented as weak** | chi-squared byte frequencies called *"Attack at dawn"* **German at p=1.35e-8**, and accuracy does not rise monotonically with length, so no cutoff fixes it |
| **There is no accuracy number at all** | not in `AGENTS.md`, not in a findings log, not in `benchmarks/`. Every claim about magic's quality in this repository is asserted |

The pattern is the charter's justification: two ranking defects in one release, found by inspection
rather than by a gate, in the one tool whose output a model is most likely to act on directly.

## Candidate scope

- **A corpus with known answers.** Layered encodings, compressed containers, real file types,
  plaintext in several languages, and deliberate near-misses. Generated where possible so it is
  regenerable rather than a frozen blob — the `english.mjs` trigram lesson, where a generator once
  read its own base64 output back in as English.
- **An accuracy figure**: how often the correct answer is rank 1, and how often it is in the top
  three. Published with the corpus so the number can be disputed.
- **A gate that can fail**, calibrated the way the benchmark gate was — a noise floor and a
  detection curve, not a threshold picked from one plausible run. This project has set three
  thresholds from a first measurement and moved two of them within days.
- Only then: ranking changes, each justified by movement in the figure.

## What it is explicitly not

- **Not a learned model.** No training data, no drift, no non-determinism in the selection path.
  The objections in [`../../v3/task-level-scoring.md`](../../v3/task-level-scoring.md) apply
  unchanged.
- **Not a change to `src/core/lib/Magic.mjs`**, which is mirrored from upstream. The re-ranking
  lives in `src/node/lib/magic.mjs`, as `promoteDecodings` already does.
- **Not a promise that language detection becomes reliable.** It may well end with a *better
  documented* estimate rather than a better one, and that is a legitimate outcome — the current
  documentation already says the estimate is never a determination.

## Trigger

**Fired**, on evidence rather than an event: two ranking defects in v3.9.0, no accuracy figure
anywhere, and a language estimator with a documented failure at p=1.35e-8.

## Kill criteria

- **The corpus cannot be built without encoding its author's assumptions.** If "the correct answer"
  turns out to be a judgement call for most inputs, a figure derived from it measures the author,
  not the tool. Say so and stop — a confident accuracy number built on a rigged corpus is worse than
  no number, and this project has already published one measurement it had to disprove itself.
- **The figure does not move** for any ranking change tried. Then the ranking is as good as this
  approach gets; record the number, keep it as a regression gate, and close the charter.
- Upstream restructures `speculativeExecution` such that the fork's re-ranking no longer applies
  cleanly. Then it is a `patches/fork` question first and a scoring question second.

## Verification

- The corpus and the figure land together, in `docs/internal/measurements/`, with the method.
- The gate verified by reintroducing the **real** defect: the v3.9.0 container-outranks-its-contents
  case, which is already reproducible and already has a test.
- `cyberchef_magic`'s emitted recipes stay bakeable — there is already a test that bakes every one,
  and it exists because the operation once emitted a pretty form that `bake` rejected.
