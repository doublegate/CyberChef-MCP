# Charter: v4.9.0 — Consolidation, and the v5.0.0 question

> Run [`../../v3/RE-MEASURE.md`](../../v3/RE-MEASURE.md) first.
>
> **Rewritten 2026-09-11.** The previous version asked the v5.0.0 question as though only the
> specification could answer it. v4.0.0 proved otherwise.

## Intent

Close the line. Consolidate what the eight charters before it left scattered, and answer the
v5.0.0 question **on evidence rather than on a number coming up**.

## What changed about the v5.0.0 question

v4.0.0 shipped on **T-13** — accumulated removals — not on any specification event. The full
reasoning is `../../internal/v4.0.0-findings-log.md` F-01, and the correction it records is the one
that governs this charter:

> All four v4.0.0 triggers were **external** specification events, so the project had no internal
> path to a major at all. v4.0.0 waited on something that might never arrive while deprecated
> surface accumulated with no mechanism able to remove it.

So there are now **two** legitimate reasons for a major, and this charter must check both:

| | Answered by |
|---|---|
| The protocol forced one | T-1 … T-12 — external, and none has fired in five releases |
| This project has surface to retire | **T-13** — internal, offline, and it is what cut v4.0.0 |

## The consolidation half

By the time this charter is taken, v4.1.0–v4.8.0 will have moved the surface, the dispatch table and
the tool set. Consolidation means:

- **Re-measure everything the line claimed.** Surfaces, index composition, test and coverage
  figures, the registry-tool count. Every release in the v3 line found at least one figure that had
  drifted since it was written, including figures written *by the release that was checking them*.
- **Reconcile the documents to the code**, once, deliberately — rather than at the end of each
  release under time pressure, which is when the `_v3` → `_v4` sweep broke seven historical image
  references in v4.0.0.
- **Archive every charter whose trigger never fired**, with a dated banner naming why. A charter
  quietly dropped reads as an oversight; a charter archived with its reasoning is a decision.
- **Audit the carried-forward list.** It has items from the v3.0.0 plan that are still true. If one
  has survived a whole major line untouched, that is a finding about the list, not about the item.

## Trigger

Both of:

- v4.1.0 and v4.2.0 have landed — the line's two fired-trigger charters — **and**
- at least three of v4.3.0–v4.8.0 have either landed or been archived. A consolidation over work
  that has not happened is a reorganisation of intentions.

## Kill criteria

- **Nothing needs consolidating.** Then fold the re-measurement into whatever minor is open and do
  not cut a release to hold it. v2.x ran to eleven minors and v3.x to eleven; there is no virtue in
  reaching v4.9.0.
- **T-13 fires before this charter is reached.** Then a major is due on its own evidence, and the
  consolidation belongs *in* that major rather than ahead of it — which is precisely how v4.0.0
  behaved.

## The question this charter must answer in writing

Not *"is it time for v5.0.0?"* — that is a number question. The two that matter:

1. **Is there advertised surface describing something already finished, withdrawn, or decided
   against?** If yes, T-13 has fired and a major is due regardless of the specification.
2. **Has the specification forced a break?** If yes, adopt it and cut. If no, say so plainly and
   ship minors — which is what the kill criterion in `v4.0.0-plan.md` has correctly said all along
   about *that* half of the question.

If both answers are no, **the honest output of this charter is a sentence saying so**, and the line
continues at v4.10.0. That is not a failure of the plan; it is the plan working.
